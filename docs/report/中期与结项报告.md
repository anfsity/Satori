# Satori 中期与结项报告

## 一、项目定位

Satori 是一个中文黑话和网络梗检索系统，目标是让用户通过白话、黑话或场景描述查询相关词条、解释和例句。

当前版本定位为检索后端，不训练大模型，不实现聊天机器人，也不在 API 契约中承诺生成式内容。

## 二、当前进度

截至 2026-05-13，本地 `main` 分支与 GitHub `origin/main` 对齐，最近主线提交为 `test: add retrieval evaluation command (#29)`。

已完成内容：

- Rust workspace 已拆分为 `core`、`api`、`indexer` 三个 crate。
- `core` 已实现卡片结构、JSON 加载、数据校验、搜索索引、关键词排序、索引文档结构和 LanceDB 文档结构。
- `api` 已实现 Axum HTTP 服务，提供 `/api/health` 和 `/api/search`，并支持通过配置启用本地 LanceDB 检索后端。
- 搜索 API 已有查询参数校验、limit 解析、JSON 错误响应和 CORS 支持。
- `indexer` 已支持本地卡片校验、`mcsrainbow/chinese-internet-jargon` 导入、索引文档 JSONL 导出、本地 LanceDB 表构建和本地检索评估。
- 文档侧已有 README、项目计划书、API 契约、机器可读 API 示例、前端集成说明和演示材料。
- 测试侧已有 API 冒烟测试、搜索质量回归测试、核心数据校验测试、LanceDB 写入测试和检索评估命令覆盖。
- GitHub Actions 已覆盖格式检查和 workspace 测试，并已配置 LanceDB 依赖所需的 `protobuf-compiler`。

按原项目计划的三阶段划分，项目已经超过中期要求，进入“后期集成与交付整理”阶段。阶段一的基础架构和阶段二的大部分数据处理/API 开发已经完成；阶段三中的测试、文档和前后端联调准备也已基本完成。

## 三、尚未完成的关键项

当前 API 默认仍使用本地 JSON 语料和内存关键词排序。配置 `SATORI_LANCEDB_PATH` 后，API 可以打开本地 LanceDB 表，生成查询向量，并按 LanceDB 返回顺序组装原有 `/api/search` 响应结构。该能力已合入 `main`。

当前默认工作区没有提交持久化的 `data/processed/lancedb` 表目录，也没有提交默认生成的 `data/processed/index_docs.jsonl` 文件。这些是本地生成产物，已通过 `.gitignore` 排除。

当前可运行默认嵌入模型配置为 `paraphrase-multilingual-MiniLM-L12-v2`，用于 `build-lancedb-index` 命令和 API 查询侧 LanceDB 检索。模型与 tokenizer 由 LanceDB 的 sentence-transformers embedding 封装加载，不作为仓库文件提交。

`BAAI/bge-small-zh-v1.5` 更适合中文检索，但当前 LanceDB Rust 的 sentence-transformers 封装会固定访问 `sentence-transformers/<model>` 仓库，不能直接加载 `BAAI/bge-small-zh-v1.5`。后续如要切回 BGE，需要补一个支持完整 Hugging Face repo id 的本地 embedding 加载实现。

Roadmap 当前仍保留 5 个 draft item：Corpus import and cleanup、Search quality regression suite、Embedding and LanceDB indexing、API contract for frontend integration、Minimal CI。这些条目对应的代码工作大多已经完成，但 GitHub Project 状态未同步；Project 中还保留一个已关闭的 LanceDB API issue 条目。后续汇报时需要手动标注“roadmap 可能滞后”。

## 四、漏洞与缺陷检查

本次检查运行了：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

检查结果：格式检查、clippy 和 workspace 测试均通过。

发现的问题与处理：

- `.gitignore` 原先没有忽略 `data/processed/index_docs.jsonl` 和 `data/processed/lancedb/`，存在误提交本地索引产物的风险。已补充忽略规则。
- API 契约文档原先在“当前实现说明”中提到后续 Embedding 和 LanceDB 切换，容易让前端误以为当前 API 已承诺模型或向量检索行为。已改为只描述当前 HTTP 契约和可配置检索后端。
- README 和 AGENTS 中已经说明 API 默认仍是内存关键词检索，配置 LanceDB 后可以启用向量检索路径。该判断与代码一致。

剩余风险：

- 检索质量仍依赖小规模固定 fixture 和关键词规则，不能代表真实大语料上的语义效果。
- 当前已有固定 fixture 的本地检索评估命令，但真实导入语料和真实 LanceDB 表上的自动化质量评估仍未完善。
- `mcsrainbow` 导入逻辑基于 Markdown 结构解析，外部源格式变化时可能需要更新解析规则。
- 当前没有限流、鉴权或部署侧保护，只适合本地和演示环境。

## 五、结项判断

如果结项标准是“可运行的后端检索原型”，当前项目已经具备结项条件：可以启动 API、读取本地语料、返回稳定 JSON，并通过测试保障基础行为。

如果结项标准是“完整语义向量检索系统”，当前已经进入最后集成阶段。剩余缺口集中在真实语料索引产物复现、检索质量评估和部署侧稳定性。

建议后续按小 issue 继续推进：

1. 整理本地索引复现文档，明确从 cards 到 index docs 到 LanceDB 的完整命令链。
2. 补充真实语料回归评估，把当前 fixture 回归扩展到导入语料的代表性查询集。
3. 同步 GitHub Project roadmap，把已完成 draft item 标记为完成或替换为下一阶段条目。
4. 验证真实本地 LanceDB 表上的 API 查询效果，再决定是否调整默认模型、索引内容或 rerank 策略。
