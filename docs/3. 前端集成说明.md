# Satori 前端集成说明

本文档面向负责前端实现的 Gemini，说明当前后端能力、接口使用方式、页面行为和实现边界。

更严格的接口字段定义以 `docs/2. API 契约.md` 和 `docs/api-examples/` 为准。本文档用于指导前端产品实现。

## 1. 前端目标

Satori 是一个中文黑话和网络梗检索工具。

前端第一版应实现一个可直接使用的搜索体验：

- 用户输入白话、黑话、网络梗或场景描述。
- 前端调用后端 `/api/search`。
- 页面展示匹配到的词条、白话解释、说明、例句和标签。
- 查询为空、无结果、加载中、后端错误时都有明确状态。

第一版不需要实现登录、收藏、编辑词条、聊天机器人或生成式回答。

## 2. 本地后端

默认启动方式：

```bash
cargo run -p satori-api
```

默认 Base URL：

```text
http://127.0.0.1:3000
```

健康检查：

```bash
curl http://127.0.0.1:3000/api/health
```

搜索示例：

```bash
curl "http://127.0.0.1:3000/api/search?q=大家先统一想法&limit=10"
```

后端已支持本地跨域调用，前端开发服务器可以从其他 localhost 端口请求 API。

## 3. API 摘要

### `GET /api/health`

用于检查后端是否可用。

成功响应：

```json
{
  "status": "ok"
}
```

### `GET /api/search`

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `q` | 是 | 搜索文本。前端应在提交前 trim，空白输入不应发请求 |
| `limit` | 否 | 返回数量。建议前端默认传 `10` |

成功响应：

```json
{
  "query": "大家先统一想法",
  "results": [
    {
      "id": "jargon_lar_tong_dui_qi",
      "term": "拉通对齐",
      "plain": "大家先统一想法",
      "explanation": "让相关的人先把目标、分工和时间说清楚。",
      "examples": ["这个需求先拉通对齐一下。"],
      "tags": ["职场", "会议", "协作"],
      "score": 1.0
    }
  ]
}
```

无匹配时：

```json
{
  "query": "完全不存在的说法",
  "results": []
}
```

错误响应：

```json
{
  "error": "invalid_query",
  "message": "q must be present, non-empty, and within the character limit"
}
```

当前错误码：

| HTTP 状态码 | `error` | 前端建议 |
| --- | --- | --- |
| `400` | `invalid_query` | 提示用户输入有效搜索内容 |
| `400` | `invalid_limit` | 使用默认 limit，并可显示普通错误提示 |
| `500` | `search_failed` | 提示后端检索暂时不可用 |

## 4. TypeScript 类型建议

```ts
export interface HealthResponse {
  status: "ok";
}

export interface SearchResponse {
  query: string;
  results: SearchResult[];
}

export interface SearchResult {
  id: string;
  term: string;
  plain: string;
  explanation: string;
  examples: string[];
  tags: string[];
  score: number;
}

export interface ApiErrorResponse {
  error: "invalid_query" | "invalid_limit" | "search_failed" | string;
  message: string;
}
```

前端可以保留未知 `error` 字符串的兜底处理，不要只接受当前枚举。

## 5. 页面与交互

第一版建议只做一个主搜索页面。

核心区域：

- 顶部应用标题：`Satori`
- 搜索输入框
- 搜索按钮
- 可选的结果数量选择，默认 `10`
- 结果列表

推荐初始状态：

- 输入框获得焦点。
- 可以展示少量示例查询按钮，例如 `大家先统一想法`、`心态崩了`、`故意搞点节目效果`。
- 示例按钮点击后直接填入并搜索。

搜索行为：

- 用户按 Enter 可以提交搜索。
- 点击搜索按钮可以提交搜索。
- 提交前对输入做 `trim()`。
- trim 后为空时，不发请求，显示本地提示。
- 请求中禁用搜索按钮或展示 loading 状态。
- 新请求开始时可以保留旧结果并显示 loading，也可以清空旧结果；保持体验一致即可。

结果展示：

- 每条结果优先突出 `term`。
- `plain` 作为人话解释放在明显位置。
- `explanation` 作为正文说明。
- `examples` 有内容时展示为例句列表。
- `tags` 有内容时展示为标签。
- `score` 可以弱化展示或不展示，不要把它解释为百分比准确率。

无结果状态：

- 文案可以表达“没有找到匹配词条”。
- 可以建议换一种说法或缩短查询。

错误状态：

- 网络错误：提示后端服务不可用或连接失败。
- `invalid_query`：提示输入有效内容。
- `search_failed`：提示检索后端暂时不可用。
- 未知错误：显示通用错误提示。

## 6. 前端实现边界

前端可以依赖：

- API 路径：`/api/health`、`/api/search`
- JSON 字段名和基础结构
- `results` 已经按后端相关性排序
- `examples` 和 `tags` 永远是数组

前端不要依赖：

- `score` 的具体算法含义
- 当前是关键词检索还是 LanceDB 检索
- 当前语料只有多少条
- 结果一定非空
- 同一个 query 的排序永远不变

后端后续可能调整检索算法、索引内容、embedding 模型或 rerank 策略，但会尽量保持 `/api/search` 的基础响应结构稳定。

## 7. API 客户端建议

建议封装一个小的 API client，而不是在组件里散落 `fetch`。

伪代码：

```ts
const API_BASE_URL =
  import.meta.env.VITE_SATORI_API_BASE_URL ?? "http://127.0.0.1:3000";

export async function searchSatori(query: string, limit = 10): Promise<SearchResponse> {
  const params = new URLSearchParams({
    q: query,
    limit: String(limit),
  });
  const response = await fetch(`${API_BASE_URL}/api/search?${params}`);
  const payload = await response.json();

  if (!response.ok) {
    throw payload as ApiErrorResponse;
  }

  return payload as SearchResponse;
}
```

注意：

- 使用 `URLSearchParams` 编码中文查询。
- 不要手写拼接未编码的 query string。
- 对非 2xx 响应也尝试读取 JSON 错误体。
- 网络异常和 JSON 解析异常要有兜底提示。

## 8. 推荐组件拆分

可以按以下组件拆分：

- `SearchPage`：页面状态管理和 API 调用。
- `SearchBox`：输入框、提交按钮、示例查询。
- `SearchResultList`：结果列表容器。
- `SearchResultItem`：单条结果展示。
- `TagList`：标签展示。
- `EmptyState`：无结果状态。
- `ErrorState`：错误状态。

如果项目规模很小，也可以先把组件保持在较少文件中，但 API 调用和 UI 展示最好分开。

## 9. 验收清单

前端实现完成后至少检查：

- 后端未启动时，页面能显示连接失败状态。
- 后端启动后，健康检查或搜索请求可正常返回。
- 输入空白内容不会发请求。
- 搜索 `大家先统一想法` 能展示 `拉通对齐`。
- 搜索 `心态崩了` 能展示 `破防了`。
- 搜索未知英文字符串能展示无结果状态。
- `limit=1` 时只展示 1 条结果。
- API 返回 400 时显示用户可理解的错误。
- 页面在移动端宽度下不出现文字重叠。

## 10. 当前后端验证状态

截至 2026-05-13，后端已经完成：

- 默认关键词检索 API。
- 可选 LanceDB 检索 API。
- `/api/search` 响应结构兼容两种检索后端。
- API 冒烟测试和回归测试。
- 本地检索评估命令 `cargo run -p satori-indexer -- evaluate-search`，当前固定用例结果为 `10 passed, 0 failed, 10 total`。

前端第一版可以直接基于默认 API 开发，不需要等待真实语料 LanceDB 质量评估完成。
